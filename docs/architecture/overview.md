# Decomp architecture

This repository reconstructs first-party functions from the shipped Rally
Trophy executable as C++ and checks the compiled x86 bodies against the PE.
The stable key for a procedure is its original address, not its guessed name.

## Scope

- Target: the locally supplied 32-bit Windows executable under `orig/`.
- Source reconstruction: `src/` and `include/`.
- Byte comparison: `tools/match.py` and `tools/objcmp.py`.
- Function inventory and work claims: `analysis/`.
- Binary evidence and subsystem notes: `docs/analysis/`.

The queue covers first-party game code. The `.cms_t` copy-protection stub and
third-party Miles, Bink, and GameSpy SDK implementations are excluded.

## Iteration

1. Pick an unclaimed function or range from `analysis/PROGRESS.md`.
2. Inspect the shipped binary and record REA Evidence IDs for non-trivial
   findings.
3. Make the smallest source change that expresses the observed behavior and
   expected compiler layout.
4. Run the focused matcher, review the generated bytes, and document the exact
   result.
5. Run the full matcher, refresh the progress report, then commit only the
   verified files owned by the iteration.

Read `analysis/NOTES.md` for compiler and source conventions. The
separate Rust behavior port is in `../Rally-Trophy-Rust`.
