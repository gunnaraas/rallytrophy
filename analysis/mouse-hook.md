# Mouse hook

`T_56b0c0` installs a thread-local `WH_MOUSE` hook on the first live instance and removes it when the last instance is destroyed. Its constructor at `0x4b6ac0` and destructor at `0x4b6bf0` now both match exactly. On hook-install failure, the constructor builds an `assertion_error` with an empty base exception message and a copied `std::string` message, then throws it. The 0x1c-byte exception object therefore contains the 0x0c-byte exception base followed by `m_message`; the constructor's compiler-generated cleanup and unwind frame are reproduced. This behavior and layout are observed in `ev_bc2bbc0de5ccf8b16837b2f02d53aeced3a7168eec3c06929969ee1ae3a61fc7`.

The callback at `0x4b6c10` first forwards negative hook codes to `CallNextHookEx`. For normal codes it clears the per-frame left/right click flags, updates the stored pointer coordinates for `WM_MOUSEMOVE`, remembers left and right button down state, and raises the corresponding click flag on release only if that button was previously down. It forwards the event after processing. This behavior is observed in `ev_6b284eb80332e3808afb2879f452be8536a671541fc828067ed8ddb1931a6601`; the callback body currently differs only at the alignment byte immediately after its return and before the switch table. The separate hook-install evidence is `ev_bc2bbc0de5ccf8b16837b2f02d53aeced3a7168eec3c06929969ee1ae3a61fc7`.

The companion inspection at `0x4b6f90` (`ev_acd26114f61223753f305655ffdd0e7e96f96503d0a1b1e328ce9c7825f682af`) confirms the keyboard callback is a separate function referenced by the keyboard hook constructor. The mouse reconstruction does not claim coverage of that callback.
