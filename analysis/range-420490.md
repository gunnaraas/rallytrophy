## Module 1: StageTable / car selection view and math helpers

The screen at `Game+0x59e4` is 0x24c bytes (`GameScreen59E4` placeholder in `include/unk_4303e0.h`). Ctor 0x4205e0 calls MenuScreen base ctor 0x4381c0, initializes string/vector-like members, and writes vptr 0x4e14ac. Its four virtual entries should be read as the first four function pointers at that table; code and slot use identify the base screen contract as dtor, Setup, Release, and Slot3. The ctor/dtor and method bodies in this range establish the object as the StageTable screen, rather than a separate Stage or Player class. Slot implementation addresses among this range include 0x420730 (dtor), 0x420db0 (main setup/frame), 0x421a80/0x421b80/0x421d00 (helper paths); 0x421e30 is an external selection operation receiving Game, Player and additional arguments.

Fields established by 0x4205e0: base occupies +0x00..+0x1f; embedded strings/vector storage starts at +0x20; vector-like groups at +0x44, +0xc4, +0xd4, +0xe4; another vector at +0xf4; data through +0x240. Exact logical labels beyond the known stage/car-selection role are not assigned without full member-use tracing. In particular +0x44 is constructed as 8 elements, +0xf4 as 2 elements, with string ctor/dtor callbacks 0x430700/0x430720 and copy helper 0x404cd0. This indicates arrays of string-bearing records.

Strings/config: initialization reads a configuration/resource path rooted at `.\data\` / stage table resources (large routine 0x420db0); the associated screen methods use UI resource IDs and text rendering through globals and MenuGame. No reliable literal `.ini` filename can be assigned from the inspected evidence. Float operations use screen dimensions global 0x56b0ac and constants from .rdata. `0x4e14ac` is the class vtable; object size 0x24c.

## Generated helpers and work groups

* Compiler/runtime generated: 0x424300 (two-word record copy), 0x424320/0x424350 (vector pointer copy/fill), 0x4244b0 (scalar deleting destructor), three `_$E` guards at 0x424380/0x425d50/0x426690, and constructor unwind callbacks 0x421a80/0x421b80. The short 0x4243d0/0x4243f0 routines are likely iterator/record thunks. 0x4205b0/0x4205c0 are static initialization/atexit support. No range-local string-template implementation bodies beyond ordinary inline VC6 string operations in screen methods.
* Suggested groups (keep each worker within a module):
  * G1 (about 2 KB): 0x420490-0x420730 math helpers and screen lifecycle.
  * G2 (large standalone): 0x420db0 (3.2 KB), StageTable setup/render.
  * G3 (about 2.7 KB): 0x421a80-0x421e30 lifecycle callbacks, list helpers, player car selection.
  * G4 (large standalone): 0x421fa0 (4.0 KB), stage/car selection presentation.
  * G5 (about 2.5 KB): 0x422fc0-0x4239c0 resource list and selection helpers.
  * G6 (about 2.7 KB): 0x423b90-0x424350 display helper and generic vector routines.
  * G7 (about 2.3 KB): 0x4243b0-0x424960 accessors, second screen lifecycle and main draw.
  * G8 (standalone): 0x425220 (2.8 KB) setup/config/resource loader.
