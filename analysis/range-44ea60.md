# Range 0x44ea60 - 0x450edf: module map (read-only raw disassembly, Patch 1.01 exe; no REA)

Method: rawdis.py over the whole range, refs.py for callers/abs refs, .rdata/.data/IAT reads with a PE section reader. "Guess" marks inference. EH handler addresses (0x4da018 ... 0x4da208) are the `push imm` after `push -1` in each SEH prologue.

## 0. Headline findings

1. **The range is one file holding one class: a MenuScreen subclass with 8 editable text slots (a "slot list" screen)**, 0x4f4 bytes, embedded in the Game object at **Game+0x2008** (Game ctor calls 0x44ea60 at 0x430455 with `lea ecx,[esi+0x2008]`; the next embedded member is at Game+0x24fc, 0x2008 + 0x4f4 = 0x24fc). It is **not** in the menu manager (the SoundMenu in the next file is). I call it `SlotMenu` (guess; behaviour below suggests a save-game / profile slot screen with a name-edit field per slot, all the data comes from the object at Game+0x2dcc, see section 1).
2. **File boundaries**: the previous file ends with the `_$E` guard stub at 0x44ea30 (init-table entry at file offset 0xefb6c); this file ends with its own stub at **0x450eb0** (48 bytes, 0x450eb0-0x450edf, followed by SoundMenu's ctor at 0x450ee0). The stub is `mov cl,[0x5826d5]; mov al,1; test al,cl; jne; or cl,al; mov [0x5826d5],cl; jmp +; push 0x402c90; call atexit(0x4c0d01); pop ecx; ret`. No file-scope statics (no initialiser pair), no function-local statics.
3. **functions.csv lists 9 functions but there are 11**: it is missing **0x44eb60** (525 instruction bytes, vtable slot 1, `Setup(Game*)`) and **0x450be0** (704 bytes, vtable slot 3, `Draw(int)`). Everything between the stubs is accounted for by: 9 csv functions + these 2 + the stub (0x450eb0).
4. **Vtable 0x4e1a4c** (read from .rdata): slot 0 = 0x44ead0 (scalar deleting dtor), slot 1 = 0x44eb60 (Setup), slot 2 = 0x43ff80 (shared `MenuScreen::Release`, ICF'd with other screens), slot 3 = 0x450be0 (Draw; in SoundMenu this slot is a `ret 4` stub, here it is real). Only abs refs to the vtable: 0x44ea60 ctor (`mov [esi],0x4e1a4c` at 0x44eaa5) and dtor 0x44eaf0 (0x44eb0d). Slots 0/1/3 are referenced as abs words at file offsets 0xe024c/0xe0250/0xe0258.
5. **`Frame` 0x44ed90 is a blocking run loop**, not a per-frame function: it pumps messages (0x4b69f0) itself and loops until Esc/close; `Run` (0x44ed70) is `vtbl[1](game); return Frame()`. The only caller of Run is 0x4485e8 (`push game; lea ecx,[game+0x2008]; call 0x44ed70`) inside a switch in another front-end screen's Frame (that code also plays Game+0x139294 "select" before other cases).
6. Same MenuScreen base as the other screens (include/unk_450ee0.h `MenuScreen`/`MenuLabel`/`UIRect`/`MenuGame`): ctor 0x4381c0, dtor 0x438210, base vtable 0x4e16dc.

### What it does (read from the code; the screen identity is a guess)
- Items: 0 = title text 0x170 (Enter on it moves the cursor to item 2 and warps the mouse onto item 2's rect, 0x44ef94-0x44f09a), 1 = "Back" (text 0x18; Enter or Esc exits, returns), 2..9 = eight slot rows. Up/Down (0x57ba4e/0x57ba50) move, with wrap rules at 0x44f238-0x44f272 (the selection never enters item 0 or 1 via Up/Down from below except the "Back" special case at 0x44f258), mouse hover through the UIRect list (`0x438f90` MenuScreen hit-test of mouse position over m_items), clicks via 0x57ba20/0x57ba24.
- Enter (0x57ba35) on a slot with kind > 0: if kind>0 and `Game::0x436250(this)` (a confirmation dialog taking the screen, guess: "overwrite?") returns 0, abort the edit; else copy the label text to the record buffer and call **`Game+0x2dcc` object**: `0x490fb0(obj, buffer)` (called from 12 places including the Player area; guess: set name/save) and `0x44d260(obj, idx-2)` (guess: write/load slot idx-2), then RefreshSlots. First Enter on a slot starts text edit (+0x4f0 = 1, `std::string::assign`/`erase` via 0x4024f0/0x408de0 with npos 0x4e1340 = 0xffffffff); typed characters come from renderer vcall 0x20 (backspace = 8 handled with an inline erase at 0x44f77c-0x44f849, otherwise append with `0x402980`/`0x402960` and a max-length check via 0x4c14e0 memmove-style helper); Esc leaves edit mode (restores the label via 0x4024f0) before it leaves the screen.
- Game+0x2dcc is the same object used by 0x42ef28, 0x42f299 (Game ctor area), 0x4307b1, 0x43327a, 0x43389c, 0x43399c, 0x492d6b: a career/profile-like manager (guess). Its methods 0x44e6a0 (`GetSlotInfo(i, record*)`) and 0x44d260 are in the previous file (0x44e3e0-0x44ea2f region).
- DrawField kinds (read from 0x44fd30): kind 1 prints text 0x9a + ": " in the left column and the pre-built value in the right column; kind 0 draws nothing; other kinds print 0x96 + ": " / the text 0x9f, 0xa0, 0xa1, 0x171 (",", " " separators are the .rdata strings " " 0x4f2e40 and ": " 0x4f75c8), use `0x4c1902(…, 10)` (itoa base 10) for numeric fields, test the global 0x501458 (same flag as the AIDriver creation guard: guess "race has opponents/network") and format the record's date and time with **GetDateFormatA / GetTimeFormatA** (IAT 0x4e10b4 / 0x4e10b8, `LOCALE_USER_DEFAULT` 0x400, `push 0x20` buffer length): so the slots show a timestamp (strongly suggests saved games or profiles).
