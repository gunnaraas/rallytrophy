# Range 0x459890 - 0x45e47f: module map (read-only raw disassembly, Patch 1.01 exe; no REA)

Method: rawdis.py of the whole range, my own per-function call/data-reference summary (calls, .rdata floats, strings), refs.py for callers and for abs references, decoder for the SEH unwind tables (eh45e.py, handler = the `push imm` after `push -1`), init-table read from the PE. "Guess" marks inference. Sizes from functions.csv; the four `_$E` stubs (0x30 bytes each) and the static-initialiser pair 0x45ad10/0x45ad20 are not in functions.csv, I addressed them separately.

## 0. Headline findings

1. **The whole range is Car member functions** (`this` = the 0x1f30c-byte Car/CarObject of unk_45e480.h, `[this+0x24]` = CarBody, `this+0x28` = Wheel[4] stride 0x330, `this+0x14fc` = Stage*, `this+0x1becc` = Player*). It is the part of the Car class that comes *before* the constructor file (0x45e480): damage, per-frame update, physics step, spawn placement, lights, sun/shadow probe. Four source files, delimited by the four `_$E` stubs (init table 0x4efba0.. = file offsets 0xefba0/a4/a8/ac/b0 hold 0x45ace0, 0x45ad10, 0x45da90, 0x45de60, 0x45e450; the previous stub is 0x459860 at 0xefb9c).
2. **No vtables, no strings, no template instances, no scalar deleting dtors, no thunks.** Not one string constant is referenced in the range. Car is non-polymorphic; the only virtual calls are *out* calls: `call [vt+0x24]` (slot 9, probably Reset) on the five particle emitters embedded in Car (0x2100, 0x222c, 0x2358, 0x2488, 0x25e8) in 0x45cc30. All other calls are direct.
3. **File 2 has the only file-scope static**: the init-table entry 0x45ad10 (`jmp 0x45ad20`) -> 0x45ad20: `[0x508f5c] = 1.0f / 9.81f` (dynamic init of a non-const float global: `fld 1.0 (0x4e1348); fdiv 9.81 (0x4e1c24); fstp [0x508f5c]`). **Nothing in the exe reads 0x508f5c** (the whole-file dword search finds only the store at 0x45ad2c), so it is a dead global from a shared header or a leftover. File 2's init table order is: static init entry (0x45ad10) first, `_$E` stub last (0x45da90). Files 1, 3, 4 have no statics (stub only).
4. **Two globals written by 0x45bc20 and read by the Wheel code**: 0x509418 (`.data`, float, = Car+0x1380 = 100.0 / dt-ms-based factor) and 0x50941c (= Car+0x137c = dt seconds). They are the `DAT_00509418` / `DAT_0050941c` of src/unk_46c2c0.cpp (Wheel friction/relaxation scales). Their definition therefore lives in file 2 (0x45bc20 is the only writer; data initial values are non-zero garbage floats 5.55689e36 / 2.35099e-38, i.e. they are plain `.data`-initialised or uninitialised BSS-like values the loader leaves, treat as `float g_a, g_b;`).
5. **The damage system is the first half of the range.** Contact buffer: `Car+0x1c914`, up to 0x100 records of 0x28 bytes, count at `Car+0x1f114` (the header's `history[0x100]` and `unk1f114` are exactly this: it is NOT a replay record array). 0x459890 appends a record, 0x45bc20/0x45b900 flush it through 0x459910 once per update (timer `Car+0x1414`). Damage state: four zone floats `Car+0x1c74c/0x1c750/0x1c754/0x1c758`, four wheel floats `Car+0x1c73c[4]`, per-wheel floats `Wheel+0x2c8` (brake damage, used by 0x45cb80) and `Wheel+0x2cc` (steering/toe damage, used by 0x45ad40), message latches `Car+0x1c900..0x1c907` (bytes), `Car+0x1c908` message id, `Car+0x1c90c` message time. These are the co-driver damage callouts (ids 0,7,2,3,5,4,6, and 8 = "more than three systems broken").
6. **`0x45a7a0` is the Car method `ApplyWheel(int n)`** (as given): it turns wheel damage `Car+0x1c73c[n]` into three per-wheel grip/spring parameters at `Car+0xce8+n*0x34+0xc/0x10/0x14` (the header's `spring[n]` blocks), using car.ini tables indexed by `Car+8` (setup index) and front/rear (`n < 2`) selection. **`0x45dac0` is `SunFactor`**, confirmed: ray test of the car's reference point against the triangle lists of a model container (3 vertex colour bytes interpolated by barycentric weights, `*1/255`), returns 1.0 when no triangle is hit.
