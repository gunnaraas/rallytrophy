## 1. Module A: shared UI geometry helpers

`0x439080` initializes a two-float point from constants at 0x579bd0/0x579bd4 (likely `HudPoint` default constructor; vector/point size 8). `0x4390a0` writes four float coordinates and enabled=1 to a 0x14-byte UIRect and is called by a large number of menu layout builders. `0x4390d0` tests whether a screen-coordinate point lies inside the rect: scales supplied x/y using current display dimensions at 0x56b0ac and constants 0x4e1350/0x4e16d4, then compares against the rect’s four floats. These types/helpers are already described in `include/unk_450ee0.h` (`HudPoint`, `UIRect`). No vtable.

Strings/constants: display mode global 0x56b0ac; scale constants 0x4e1350 and 0x4e16d4; point default constants 0x579bd0 and 0x579bd4. The stub at 0x439140 has guard byte 0x5826d5, mask 1, and registers `atexit(0x402c90)`.

## 2. Module B: MenuScreenA48, 0x439170-0x43a35f

Class is the MenuScreen-derived screen at `MenuManager+0xa48`; MenuManager is embedded at `Game+0x2df4`, so this screen begins at `Game+0x383c`. Exact size **0x2ac** (as specified in the adjacent manager map). Base is 0x20 bytes (`MenuScreen`, vtable base 0x4e16dc); ctor calls base ctor 0x4381c0, constructs label arrays by `MenuLabel` vec callbacks 0x430700/0x430720, then writes derived vtable **0x4e1724**. The arrays observed are five labels at +0x20, two at +0xd4, four at +0x11c, and seven at +0x1ac (last ends at +0x2a4); selected index +8 starts zero. Dtor restores derived vptr, calls shared `MenuScreen::Release` 0x43ff80, destroys arrays in reverse, and calls base dtor 0x438210. The item/text IDs assigned by Setup are 0x119, 0x11a, 0x11c, 0x11b and 0x18 (Back); other title/labels are text resources. The visible layout uses display scale 1/1024 and 1/768 and renderer/text helpers from the existing menu-screen family. This is a menu/settings screen (exact user-facing identity is a guess; resolve text IDs against the complete language table before naming it).

## 3. Module C: screen at MenuManager+0x8dc, 0x43a390-0x43c55f

> **Corrections (Claude review, 2026-10-23).** Module C's screen is **not** the menu manager's +0x8dc member: the Game constructor builds it at **Game+0x1378** (`lea ecx,[esi+0x1378]; call 0x43a3c0` at 0x43041a), right after the service screen at Game+0x11a4 and before the player-name screen at Game+0x14cc, so it is at most **0x154 bytes**. Vtable 0x4e1764 slot 3 is **0x43b1d0** (the 5003-byte function, its Draw), not the shared empty 0x4414c0. The manager's +0x8dc screen (ctor 0x424410) lives in another module.

Ctor 0x43a3c0 calls `MenuScreen` base ctor and writes vtable **0x4e1764**. Game ctor passes its embedded address at 0x430425; Game dtor calls 0x43a440 at 0x43096f. The object begins at `MenuManager+0x8dc`, hence `Game+0x36d0`. Size is **0x2ac** (screen shape inferred from neighboring embedded-screen allocation/manager layout; verify against ctor's highest field and manager size). Base fields +0..+0x1f are the known `MenuScreen`; +0x24 and +0x28 hold Sprite pointers initialized null, +0x08 selected starts 1, and +0x2c is used as frame/input state. Constructor stores a text ID 0x28 via `GetText` and writes it to global 0x4f8d44 (likely global caption/name cache). Setup 0x43a490 has a SEH frame and allocates two 0xd4 Sprite objects and a 0x68 Texture from path 0x4f8d7c with flags 0x841; it also configures labels/rects and texture upload. Release 0x43a640 frees screen resources; Run/Frame at 0x43a6e0 is the large modal update/draw loop. 0x43ad80 is a layout/rect builder, and 0x43afa0 is a helper called at the beginning of the main loop (likely per-frame setup/input housekeeping). 0x43b1d0 is the largest function and owns much of the menu's selection/input/drawing work. Existing dependencies: `MenuScreen`, `MenuLabel`, `UIRect`, `MenuGame`/Game view, Sprite, Texture, TextRenderer, Config, and NetRace.
