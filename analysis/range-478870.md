# Range 0x478870 - 0x47c45f: module map (read-only raw disassembly, Patch 1.01 exe; no REA)

Method: rawdis.py plus refs.py (callers, abs refs), .rdata reads (vtables, float tables). "Guess" marks inference. EH handler addresses are the `push imm` after `push -1` in each SEH prologue.

## 0. Headline findings

1. **Five source files, all in the particle/effect family** (guard stubs `mov cl,[0x5826d5]; ... push 0x402c90; call atexit(0x4c0d01)` at 0x478bb0, 0x479140, 0x47b490, 0x47c3a0, 0x47c430):
   F1 `ParticlePool` (0x478870-0x478bdf), F2 Effect base class plus the shared sprite tables (0x478be0-0x47916f), F3 the **wheel/slide emitter at Car+0x222c** (vtable 0x4e2204, 0x479170-0x47b4bf), F4 the **ballistic emitter at Car+0x2488** (vtable 0x4e2260, 0x47b4c0-0x47c3cf), F5 two orphan static float initialisers (0x47c3d0-0x47c45f, no functions).
2. **No vtable lives in F1 or F5.** Three vtables are in .rdata: 0x4e2124 (Effect base, ctor 0x478e80), 0x4e2204 (F3 class), 0x4e2260 (F4 class). All have exactly 10 slots followed by float constants of the owning file (see section 2).
3. **Car+0x222c is NOT the same class as Car+0x2358.** 47c460 map lists them as siblings: correct. F3 (`CarEmitterB`, size 0x12c, no extra fields beyond the base) and F4 (`CarEmitterC`, size 0x160) are two more `Effect` subclasses. F3 has a `Spawn` dispatcher with 5 cases (same stdcall `(type, a, b, car, body)` shape as 0x47c790) and 5 spawn cores; F4 has no dispatcher, only an `Emit(pos, dir, a, b)` that calls one core twice.
4. **Sin/cos table byte order correction**: the 1024-entry table at 0x561ec0 is `[i*8] = cos(i*2pi/1024)`, `[i*8+4] = sin(...)` (init 0x478f50: `fcos -> [eax-8]`, `fsin -> [eax-4]`). 47c460 map says sin first; it is cos first. The tables live in .bss and are filled lazily by 0x478f50, called from the Effect base ctor (guard dword 0x563ec0).
5. The six lookup tables (all `Vec2`-like 8-byte elements, empty ctor 0x490ad0 / empty dtor 0x402c90 via EH vector iterators 0x4c11f4/0x4c1116) are dynamic-initialised by static-initialiser pairs at the start of F2 (0x478be0 ... 0x478e10). Their dtors are registered with atexit and guarded by bits 1,2,4,8,0x10,0x20 of the byte at 0x561eb8.
6. F5 (0x47c3d0 and 0x47c400) only stores `1/0.3` into global 0x563f5c and `1/(1-0.3)` into 0x563f58 (constant 0x4e2298 = 0.3). Nothing in .text reads 0x563f5c/0x563f58 (abs-ref scan finds only the two stores). So F5 is a source file whose whole content is two (unused) file-scope float constants; it still needs the guard stub (it is `#include`-ing the STL headers).
7. Function-level static caches (VC6 "first call" guard byte plus three `1/(hi-lo)` floats) are used in each of the 5 F3 cores and in each F3 ctor (see below). They must be reproduced with `static` locals to match the guard-bit code.
8. functions.csv has holes: 0x478be0/0x478c20/0x478c50/0x478c90/..., and the 5 stubs are not listed (they are listed separately here). The 39-function count of the brief matches csv; this map adds 24 more tiny entries (static initialiser pieces and stubs).
